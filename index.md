# Введение

Данная инструкция предназначена для проведения пилотных проектов и носит ознакомительный характер. Рекомендуется ознакомиться с документацией решения vGate на сайте «Код Безопасности» [здесь](https://www.securitycode.ru/products/vgate/?tab=support).

Ниже приведен краткий сценарий развертывания и настройки ПО vGate.

1. **Ознакомьтесь с ограничениями использования продукта** в Release Notes:
   - [Release Notes vGate 5.2 (сертификат — сентябрь 2026)](https://docs.securitycode.ru/products/vgate_r2_5_2/AdminGuide%20-%20Operational/HardwareAndSoftwareRequirements/).
   - [Release Notes vGate 5.1 (сертифицирована)](https://www.securitycode.ru/upload/iblock/372/dml472f0ce9qmtxi2dixuircqf8vkatv/Release%20Notes.pdf)

2. **Ознакомьтесь с системными требованиями**:
   - [Системные требования vGate 5.2 (сертификат — сентябрь 2026)](https://www.securitycode.ru/upload/iblock/6e4/3auc6524w0w2p0xrmlej3jbvy166nra0/Release%20Notes.pdf).
   - [Системные требования vGate 5.1 (сертифицирована)](https://docs.securitycode.ru/products/vgate_r2_5_1/AdminGuide%20-%20Operational/HardwareAndSoftwareRequirements/)

3. **Выберите способ маршрутизации трафика**. Режим маршрутизации трафика напрямую не влияет на функции безопасности vGate. Режим маршрутизации трафика определяет принцип внедрения решения в существующую сеть:
   - с помощью сервера авторизации (Router Mode);
   - с помощью отдельного маршрутизатора (Simple Mode).

Трафик к защищаемым серверам из внешней сети администрирования должен идти **только через сервер авторизации vGate** (или через маршрутизатор с перенаправлением на vGate). Для этого необходимо настроить маршрутизацию сетевого трафика между рабочими местами администраторов и сетью, в которой размещаются защищаемые серверы и другие элементы виртуальной инфраструктуры.

[Примеры настройки перенаправления трафика на vGate на различных маршрутизаторах](#примеры-настройки-перенаправления-трафика-на-сервер-авторизации)

# Выбор способа маршрутизации трафика

## Режим Router

<figure style="text-align: center;">
  <img src="./images/router_mode_pic_500x317.png" alt="Схема маршрутизации в режиме Router" style="max-width: 80%; height: auto; border: 1px solid #ddd; border-radius: 4px;">
  <figcaption style="font-style: italic; color: #555; margin-top: 5px;">
    Схема маршрутизации в режиме Router
  </figcaption>
</figure>

**Условия и настройка:**

- Защищаемые серверы должны быть расположены в **отдельной подсети**.
- На всех защищаемых серверах в качестве **шлюза по умолчанию** следует указать IP-адрес сервера авторизации во **внутренней** сети администрирования.
- На всех рабочих местах АВИ в качестве **шлюза по умолчанию** следует указать IP-адрес сервера авторизации во **внешней** сети администрирования.

## Режим Simple

<figure style="text-align: center;">
  <img src="./images/simple_mode_pic_600x338.png" alt="Схема маршрутизации в режиме Simple" style="max-width: 80%; height: auto; border: 1px solid #ddd; border-radius: 4px;">
  <figcaption style="font-style: italic; color: #555; margin-top: 5px;">
    Схема маршрутизации в режиме Simple
  </figcaption>
</figure>

**Условия и настройка:**

- Данный режим рекомендуется использовать, если в сети уже есть **сертифицированный межсетевой экран (маршрутизатор)**, фильтрующий трафик к защищаемым серверам, и реконфигурация существующей сети не предполагается.
- Сервер авторизации размещается во **внутренней сети администрирования**, то есть в той же подсети, в которой размещены защищаемые серверы.
- В настройках маршрутизатора необходимо создать правила **перенаправления управляющего трафика** с рабочих мест АВИ и АИБ к защищаемым серверам через сервер авторизации vGate.

> **Подробнее:** см. раздел [Совместная работа с маршрутизатором](https://docs.securitycode.ru/products/vgate_r2_5_2/AdminGuide%20-%20Operational/OperationUsingRouter/).

> **Примечание:** Если vGate планируется использовать только в качестве межсетевого экрана (без функций СЗИ), маршрутизацию трафика рекомендуется настраивать в режиме Simple. Подробнее об особенностях конфигурации для данного случая см. в разделе [Развертывание vGate в качестве межсетевого экрана](https://docs.securitycode.ru/products/vgate_r2_5_2/AdminGuide%20-%20Operational/vGateAsFirewallOnly/).

# Подготовка сетевых интерфейсов

Порядок настройки сетевых интерфейсов различается в зависимости от выбранного режима и представлен в разделе **[Подготовка сетевых интерфейсов](https://docs.securitycode.ru/products/vgate_r2_5_2/AdminGuide%20-%20Operational/NetworkInterfaceSetupNew/)**.

**Рекомендуемые параметры**

До установки компонентов vGate необходимо выполнить конфигурирование сети, руководствуясь следующими правилами:

- **Внутренняя сеть администрирования** — сеть, в которой размещаются защищаемые серверы и другие элементы виртуальной инфраструктуры. Данную сеть рекомендуется отделить от сети виртуальных машин и других сетей виртуальной инфраструктуры.
- **Внешняя сеть администрирования** — сеть, в которой размещаются рабочие места АВИ и АИБ.
- **Сеть резервирования** — сеть, в которой расположен резервный сервер авторизации vGate.
- Если в виртуальной инфраструктуре используются функции **vMotion** и **Fault Tolerance**, рекомендуется организовать отдельную сеть репликации виртуальных машин, отделив ее от сетей администрирования и сетей виртуальных машин.
- Если данные виртуальных машин хранятся за пределами серверов виртуализации в отдельной системе хранения, рекомендуется создать сеть передачи данных на основе технологии **Ethernet (iSCSI)** или **Fibre Channel (FC)**. При необходимости сеть передачи данных и сеть репликации виртуальных машин могут быть совмещены.

# Требования к оборудованию

Для работы в сети, сконфигурированной таким образом, серверы виртуализации должны иметь необходимое число независимых Ethernet-интерфейсов.

> **Внимание!**  
> Не рекомендуется использование протокола **DHCP** для Ethernet-интерфейсов, подключенных к защищаемому периметру сети администрирования.

# Настройка DNS

При наличии DNS-сервера необходимо настроить **А-запись** в прямой и обратной зонах DNS с использованием **FQDN** основного сервера авторизации vGate.

В случае отсутствия DNS-сервера нужно сопоставить IPv4-адрес и FQDN основного сервера авторизации в файлах:

- **На рабочем месте АВИ с ОС Windows:**  
  `C:\Windows\system32\drivers\etc\hosts`

- **На сервере авторизации vGate (основном и резервном):**  
  `/etc/hosts`

> **Внимание!**  
> Доменному имени (FQDN) сервера авторизации vGate должен соответствовать **только один** IP-адрес.

Аналогично необходимо сопоставить IPv4-адреса и FQDN для всех защищаемых серверов (кроме автономных, если доступ к ним осуществляется без использования доменных имён).

> **Важно:**  
> Чтобы DNS-запросы для сопоставления FQDN и IP-адресов не блокировались ПО vGate, настройте взаимодействие с DNS-сервером **в обход сервера авторизации vGate**.

# Примеры настройки перенаправления трафика на Сервер Авторизации

Ниже приведены примеры настройки статических маршрутов на различных типах маршрутизаторов для перенаправления трафика к защищаемым серверам через Сервер Авторизации vGate.

## Континент-4

Подробная инструкция: [Создание маршрута в Континент-4](https://docs.securitycode.ru/products/kontinent_4_1_7/Topics_Continent/Network/StaticheskayaMarshrutizaciya/)

### Настройка в Менеджере конфигурации (МК)

1. В разделе «Структура» МК выберите нужный УБ и вызовите окно настройки свойств.
2. В левой части окна в разделе «Узел безопасности» выберите пункт «Статические маршруты». В правой части окна отобразится список статических маршрутов. Если настройка статической маршрутизации не выполнялась, список будет пустым.

#### Добавление маршрута к зарегистрированному сетевому объекту ЦУС

3. Нажмите на стрелку справа от кнопки «Добавить маршрут» и выберите пункт «Сетевой объект». Появится окно «Маршрут».
4. В поле «Назначение» нажмите на стрелку и выберите сетевой объект ЦУС. Укажите следующий узел по маршруту и введите метрику.

> **Примечание**  
> Для одного и того же сетевого объекта можно задать несколько маршрутов, в каждом из которых будет свой следующий узел. В случае недоступности указанного в маршруте следующего узла будет выбран другой маршрут. С помощью метрики задаются приоритеты маршрутов. Чем выше значение метрики, тем ниже приоритет маршрута. Высшему приоритету соответствует значение 0.

5. Нажмите кнопку «ОК». Маршрут будет добавлен в список.

#### Добавление маршрута к незарегистрированному сетевому объекту

6. Нажмите кнопку «Добавить маршрут». Появится окно «Маршрут».
7. Укажите IP-адрес объекта назначения, следующий узел по маршруту и метрику (см. примечание выше). Нажмите кнопку «ОК». Список дополнится строкой нового маршрута.

#### Сохранение изменений

8. После проведения всех необходимых настроек сохраните изменения в конфигурации ЦУС и установите политику на компоненты комплекса с измененными параметрами.

#### Редактирование и удаление маршрутов в МК

1. В разделе «Структура» МК выберите нужный УБ и вызовите окно настройки свойств.
2. В левой части окна в разделе «Узел безопасности» выберите пункт «Статические маршруты».
3. Для изменения маршрута нажмите кнопку редактирования, внесите изменения в появившемся окне и нажмите «ОК».
4. Для удаления записи выберите нужную строку и нажмите кнопку удаления. Выбранная запись будет удалена.
5. Сохраните изменения в конфигурации ЦУС и установите политику на компоненты комплекса.

### Настройка статических маршрутов при локальном управлении

1. В меню настроек выберите пункт «Сеть» и нажмите `Enter`. Появится окно «Сетевые настройки».
2. Выберите пункт «Статические маршруты» и нажмите `Enter`. Появится окно «Статические маршруты».

#### Создание нового маршрута

3. Нажмите клавишу `n` для создания нового маршрута.

> **Примечание**  
> Для редактирования имеющегося маршрута выберите его в списке и нажмите `Enter`, для удаления – `Del`.

Появится окно «Новый маршрут».

4. Введите IP-адрес удаленного сетевого объекта, укажите шлюз и введите метрику (см. примечание выше). Нажмите `Enter`. При доступности шлюза маршрут будет создан, и вы вернетесь в окно «Статические маршруты». При необходимости добавления других маршрутов повторите пп. 3–4.

#### Применение изменений

5. Для применения новых параметров вернитесь в меню настроек, выберите пункт «Применить локальную политику» и нажмите `Enter`.

> **Примечание**  
> При изменении локальной конфигурации достаточно одного применения локальной политики после выполнения всех настроек.

6. Дождитесь завершения операции и подтвердите изменения на ЦУС локально или средствами МК.
